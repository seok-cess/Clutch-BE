# 확정 요구사항

> 상태: 과제 원문 반영  
> 기준 출처: [과제 원문](assignment.md)  
> 미반영 출처: 멘토 답변과 후속 팀 결정

현재 문서는 `백엔드 종합 주제.png`에 명시된 조건만 구현 기준으로 정리한다. 원문에 없는
수치나 판정 기준은 임의로 확정하지 않으며, 멘토 답변과 팀 결정은 출처를 확인한 뒤 추가한다.

## 작성 기준

- 시스템이 만족해야 할 조건과 이를 확인할 기준을 함께 기록한다.
- 구현 방식, 담당자와 진행 상태는 요구사항 자체와 분리한다.
- 담당자와 진행 상태는 Jira에서 관리하며 이 문서에 중복해서 기록하지 않는다.

## 필수 요구사항

| 구분 | 요구사항 | 확인 기준 | 출처 |
|---|---|---|---|
| 사용자 | 가상 회원 정보가 이미 존재한다고 가정하고 회원가입과 로그인을 구현 범위에서 제외한다. | 회원가입·로그인 없이 가상 사용자로 필수 시나리오를 수행할 수 있다. | 과제 원문 |
| 개인정보 | 로그와 응답 데이터 등에 포함되는 개인정보를 반드시 마스킹한다. | 개인정보가 포함될 수 있는 로그와 응답 경로에서 원문 값이 그대로 노출되지 않는다. | 과제 원문 |
| 기획 데이터 | 쿠폰과 캠페인은 가상 데이터로 구성하며 쿠폰 종류와 할인 정책은 팀이 정의한다. | 테스트 시나리오에 필요한 가상 쿠폰·캠페인 데이터가 존재한다. | 과제 원문 |
| 대량 데이터 | 가상 사용자 100만 명과 쿠폰 발급 이력 300만 건을 생성하여 적재한다. | 사용자 수가 100만 명 이상이고 발급 이력이 300만 건 이상이다. | 과제 원문 |
| 외부 연동 | 알림 발송 등 외부 연동은 Mocking 처리한다. | 필수 시나리오가 실제 외부 서비스 없이 실행된다. | 과제 원문 |
| 선착순 발급 | 한정 수량 쿠폰을 선착순으로 발급한다. | 선착순 판정 기준은 멘토 답변 또는 팀 결정으로 추가 확정해야 한다. | 과제 원문 |
| 재고 정합성 | 재고 10,000장에 20,000명이 동시에 요청해도 초과 발급이 없어야 한다. | 최종 발급 수량이 10,000장을 초과하지 않는다. 동시 요청의 구체적인 부하 조건은 추가 확정이 필요하다. | 과제 원문 |
| 중복 발급 | 한 사람은 쿠폰을 최대 한 장만 발급받을 수 있다. | 동일 사용자가 같은 발급 기회에서 두 장 이상 발급받지 않는다. 적용 범위는 추가 확정이 필요하다. | 과제 원문 |
| 부하 테스트 | 트래픽이 몰리는 상황을 부하 테스트로 직접 재현하고 시연한다. | 재현 가능한 부하 테스트 실행 방법과 결과가 존재한다. | 과제 원문 |
| 실행 안내 | 부하 테스트 시작 가이드를 제공한다. | 다른 팀원이 저장소 문서만으로 부하 테스트를 시작할 수 있다. | 과제 원문 |
| 상태 관리 | 쿠폰의 발급·사용·취소·만료 상태를 관리한다. | 각 상태와 허용된 상태 전이가 코드와 데이터에 정의되어 있다. | 과제 원문 |
| 중복 상태 변경 | 동일한 상태 변경 요청이 반복되거나 동시에 발생해도 한 번만 반영한다. | 중복·동시 요청에서 하나의 상태 전이만 성공한다. | 과제 원문 |
| 데이터 정합성 | 어떤 상황에서도 쿠폰 이력과 재고가 어긋나지 않아야 한다. | 정합성 검사에서 이력·실제 쿠폰·재고 불일치가 0건이다. | 과제 원문 |
| 자체 검증 | 검증 쿼리나 검증 배치 등 정합성을 스스로 검증할 수단을 구현한다. | 저장소에 재실행 가능한 검증 도구와 실행 방법이 있다. | 과제 원문 |
| 전체 검증 | 발급 이력 300만 건 전체를 대상으로 검증한다. | 검증 대상 발급 이력이 300만 건 이상이며 표본 추출이 아닌 전체 집계를 사용한다. | 과제 원문 |
| 결정론 | 같은 데이터를 기준으로 검증을 다시 실행하면 같은 결과가 나와야 한다. | 동일 스냅샷 또는 동일 데이터셋에서 핵심 판정과 비교값이 동일하다. | 과제 원문 |

## 평가 대상이 아닌 항목

- 가상 사용자와 발급 이력의 생성·적재 속도
- 부하 테스트 도구 선택과 처리량
- 정합성 검증 실행 시간

평가 대상이 아니라는 것은 구현하지 않아도 된다는 뜻이 아니다. 요구된 데이터, 부하 재현과
전체 정합성 검증 결과는 제공해야 한다.

## 선택 요구사항

| 요구사항 | 확인 기준 | 출처 |
|---|---|---|
| 쿠폰 오픈 시각 예약 | 예약된 시각에 발급 기회가 열린다. | 과제 원문 선택사항 |
| 발급 현황 실시간 조회 | 발급 중인 쿠폰의 현황을 실시간으로 확인할 수 있다. | 과제 원문 선택사항 |
| 검증 결과 리포트 자동화 | 검증 실행 결과를 사람이 확인할 수 있는 리포트로 생성한다. | 과제 원문 선택사항 |

## 추가 확정이 필요한 항목

- 20,000명 동시 요청의 ramp-up 시간과 실행기 구성
- 선착순 판정에 사용할 기준 시각과 요청 순서
- “1인 최대 1매”의 적용 범위가 캠페인, 회차 또는 쿠폰 항목 중 무엇인지
- Mocking 처리해야 하는 외부 연동의 구체적인 범위
- 검증 결정론을 판단할 동일 데이터셋과 비교값의 기준

위 항목은 멘토 답변 또는 팀 결정의 출처가 확인되기 전까지 임의로 확정하지 않는다.
