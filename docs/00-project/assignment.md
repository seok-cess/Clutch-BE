# 과제 원문

> 상태: 원문 반영
> 출처: 종합프로젝트 공유 문서의 `백엔드 종합 주제.png`
> 주제: 대규모 트래픽 선착순 쿠폰 발급 시스템

이 문서는 과제 출제자가 제공한 백엔드 프로젝트 주제와 조건을 보존한다. 구현 방식에 대한
팀의 해석과 멘토 답변은 [확정 요구사항](requirements.md)에서 별도로 관리한다.

## 전체 전제 조건

- 가상 회원 정보가 있다고 가정한다. 회원가입과 로그인은 처리하지 않는다.
- 개인정보는 로그 및 응답 데이터 등에서 반드시 마스킹 처리한다.
- 쿠폰과 캠페인 정보는 가상으로 생성하며, 쿠폰 종류와 할인 정책 등의 기획은 팀이 정한다.
- 가상 사용자 100만 명과 발급 이력 300만 건의 더미데이터를 생성하여 적재한다.
  생성 및 적재 속도 자체는 평가하지 않는다.
- 알림 발송 등 외부 연동은 Mocking 처리한다.

## 쿠폰 발급 시스템

- 한정 수량 쿠폰을 선착순으로 발급한다.
- 재고 10,000장에 20,000명이 동시에 요청해도 초과 발급은 0건이어야 하며,
  한 사람은 최대 한 장만 발급받을 수 있어야 한다.
- 트래픽이 몰리는 상황을 부하 테스트로 직접 재현하고 시연한다.
- JMeter, k6, 자체 클라이언트 등 도구 선택은 자유다.
- 부하 테스트 시작 가이드를 제공한다.
- 도구와 처리량은 평가하지 않는다.

### 선택사항

- 오픈 시각 예약
- 발급 현황 실시간 조회

## 쿠폰 정합성 검증

- 발급, 사용, 취소, 만료 등 쿠폰의 전체 상태를 관리한다.
- 동일한 상태 변경 요청이 반복되거나 동시에 발생해도 한 번만 반영되어야 한다.
- 어떤 상황에서도 이력과 재고가 어긋나지 않아야 한다.
- 검증 쿼리나 검증 배치 등 정합성을 스스로 검증할 수 있는 수단을 함께 구현한다.
- 검증은 300만 건 전체를 대상으로 한다.
- 같은 데이터를 기준으로 다시 실행하면 같은 결과가 나와야 한다.
- 검증 실행 시간은 평가하지 않는다.

### 선택사항

- 검증 결과 리포트 자동화

## 주제 선정 설명

이 과제는 커머스 서비스에서 트래픽이 가장 집중되는 순간인 선착순 쿠폰 발급을 소재로 한
동시성·정합성 프로젝트다. 적은 동시 요청으로 시작할 수 있지만 정확히 해결하기는 어렵고,
대규모 트래픽 환경에서 동시성 제어, 데이터 정합성 설계와 검증을 압축적으로 경험하는 것을
목적으로 한다. 모든 데이터는 가상이며 공개된 서비스 이용 장면을 각색한 교육용 시나리오다.

## 원문 해석 시 주의사항

- 원문은 20,000명의 요청을 “동시 요청”으로 표현하지만 구체적인 ramp-up 시간은 제시하지 않는다.
- “선착순”을 판정할 기준 시각과 동률 처리 방식은 원문에 정의되어 있지 않다.
- 필수사항과 선택사항을 구분하며, 선택사항을 필수 완료 조건으로 간주하지 않는다.
- 위의 모호한 조건은 멘토 답변이나 팀 결정이 확인된 후 `requirements.md`에 근거와 함께 반영한다.
