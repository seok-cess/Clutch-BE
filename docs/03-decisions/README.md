# Architecture Decision Records

ADR(Architecture Decision Record)은 쉽게 말해 **팀이 합의한 중요한 기술적 결정을 기록하는 문서**다.

단순히 무엇을 선택했는지만 적는 것이 아니라, 어떤 문제를 해결하기 위한 결정인지, 다른 대안은 무엇이었는지, 왜 현재 방식을 선택했는지와 그 결정으로 발생하는 영향을 함께 기록한다. 이를 통해 시간이 지난 뒤에도 결정의 배경과 변경 이력을 확인할 수 있다.

ADR은 구현 작업을 관리하는 Jira 이슈와 역할이 다르다.

- ADR: 어떤 기술적 방법을 선택했고 왜 선택했는지 기록한다.
- Jira: 해당 결정을 구현하기 위해 누가 무엇을 언제 작업할지 관리한다.
- 도메인 문서: 기술 구현과 관계없이 서비스가 반드시 보장해야 하는 업무 규칙을 기록한다.

## 작성 대상

- 여러 대안 중 하나를 선택한 결정
- 데이터 정합성, 동시성 또는 장애 처리 방식에 영향을 주는 결정
- 저장소, 메시징과 외부 연동 구조에 영향을 주는 결정
- 변경 비용이 커서 선택 배경을 보존해야 하는 결정

단순한 아이디어나 논의 중인 내용을 확정된 결정처럼 기록하지 않는다. 논의 중인 ADR은 `Proposed`, 팀에서 합의해 적용할 ADR은 `Accepted` 상태를 사용한다.

## 파일 이름

```text
NNN-short-description.md
```

예시:

```text
001-coupon-stock-management.md
002-coupon-event-delivery.md
```

새 ADR은 `template.md`를 복사해 작성한다.
