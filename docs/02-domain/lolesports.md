# LoL Esports 데이터 도메인 규칙

## 범위

이 문서는 LoL Esports의 일정·순위·경기·라이브 통계를 CLUTCH가 수집, 캐시, 영속화해
화면과 다른 도메인에 제공하는 방식을 설명한다. 매치와 세트의 상태·결과 계약은
[`match-set-result.md`](match-set-result.md)를 따른다.

## 모델

- **매치(`esports_match`)**: 외부 `matchId`로 식별하는 다전제 경기다. 리그, 대회,
  블록, 시작 시각, 최대 세트 수와 전체 상태를 보관한다.
- **매치 팀(`match_team`)**: 한 매치의 참가 팀과 외부 팀 ID, 팀 코드, 승패와 세트
  승수를 보관한다.
- **세트(`esports_game`)**: 매치 안의 한 게임이다. 외부 `gameId`와 세트 번호로
  식별하며, 종료와 승자 확정 시각을 별도로 기록한다.
- **세트 통계**: 종료된 세트에서 선수 최종 기록과 타임라인 포인트·오브젝트 이벤트를
  저장한다. 라이브 화면은 우선 인메모리 캐시를 사용하고, 종료·적재된 경기는 저장된
  통계로도 조회할 수 있다.

## 데이터 경로

```text
외부 esports API / livestats
        ↓ 폴링
인메모리 캐시 ──→ 일정·순위·라이브 API
        ↓ 종료 세트 또는 과거 경기 적재
MySQL ──────────→ 과거 세트·통계·시즌 집계 API
```

- 사용자용 조회 API는 외부 API를 요청마다 직접 호출하지 않는다.
- 캐시에 없는 과거 세트는 온디맨드 적재를 시도한다. 적재가 완료된 세트는 이후 DB에서
  제공한다.
- 과거 데이터 대량 적재는 별도 운영 API로 비동기 실행한다. 라이브 요청 처리 경로에서
  대량 백필을 수행하지 않는다.

## 외부 소스와 재생

- 외부 소스는 `REAL` 또는 `STUB`이다. STUB은 시연·테스트용 replay 서버를 가리킨다.
- 소스 전환은 읽기/쓰기 잠금으로 폴링과 직렬화하며, 전환 시 캐시와 과거 적재의
  인메모리 상태를 초기화한다. 서로 다른 소스의 프레임을 섞지 않기 위한 규칙이다.
- STUB 전환 전에는 replay 서버 상태를 확인한다. 서버를 시작하거나 fixture 재생을
  시작하는 동작은 별도의 replay 제어 유스케이스다.

## 시간과 확정성

- 외부에서 받은 시각은 UTC 기준으로 보관하고, API는 ISO-8601 문자열로 노출한다.
- `livestats gameState=finished`는 세트가 끝났다는 빠른 신호다. 세트 승자는 외부
  `gameWins` 증가로 확정하며, 이 값은 종료보다 늦을 수 있다.
- 세트 종료, 세트 승자 확정, 매치 최종 종료를 같은 시점으로 취급하지 않는다.
  배팅 정산과 결과 기반 처리는 확정된 승자만 사용한다.
