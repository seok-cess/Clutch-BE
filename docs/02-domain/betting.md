# 승패 배팅 도메인 규칙

## 범위

이 문서는 한 매치의 세트 승리 팀을 예측하는 배팅의 이벤트 생성, 배팅 가능 시간, 등록, 정산,
환불과 포인트 배분 규칙을 정의한다. 세트 종료와 승자 확정에 사용하는 외부 데이터 계약은
[`lolesports.md`](lolesports.md)를 따른다.

## 현재 제공 범위

- 배팅 대상은 매치 전체가 아니라 **매치의 각 세트 승리 팀**이다.
- 한 배팅 이벤트는 정확히 두 참가 팀 중 승리할 한 팀을 선택하게 한다.
- 첫 용, 첫 퍼블, 바론 등 세트 승패 이외의 예측 항목은 현재 제공 범위에 포함하지 않는다.
- 다전제의 최대 세트가 끝나면 다음 세트 이벤트를 만들지 않는다.

## 주요 개념

- 배팅 이벤트: 특정 매치의 한 세트에 대해 배팅을 받을 수 있는 기간과 결과를 나타낸다.
- 사용자 배팅: 사용자가 배팅 이벤트에서 선택한 승리 팀과 배팅 포인트다.
- 총 풀: 한 배팅 이벤트에 등록된 모든 사용자 배팅 포인트의 합이다.
- 적중 배팅금 합: 확정된 승리 팀을 선택한 사용자 배팅 포인트의 합이다.
- 배당 풀: 총 풀에서 운영 수수료를 제외하고 적중자에게 배분할 포인트다.

## 이벤트 생명주기

| 상태 | 의미 |
|---|---|
| `OPEN` | 배팅 등록을 받을 수 있는 기간이다. |
| `CLOSED` | 배팅 등록은 끝났고 세트 승자 확정 또는 정산을 기다리는 상태다. |
| `SETTLED` | 승자 확정과 사용자 배팅 정산이 모두 끝난 상태다. |
| `CANCELLED` | 진행되지 않은 세트 등으로 배팅을 환불할 상태다. |

- 동일 매치·세트 조합에는 배팅 이벤트를 하나만 둔다.
- 이미 열린 미래 세트가 실제로 진행되지 않으면 `CANCELLED` 처리한다.
- `OPEN` 상태라도 현재 시각이 이벤트의 배팅 가능 기간 밖이면 배팅을 받을 수 없다.

## 배팅 가능 시간

시간은 UTC로 저장·처리한다. 아래 20분과 1분은 현재 기본 설정값이며,
`betting` 설정으로 조정할 수 있다.

### 첫 세트

- 공식 일정 시작 20분 전부터 배팅을 연다.
- 공식 일정 또는 esports-api의 `inProgress` 상태만으로는 배팅을 닫지 않는다.
- 실제 livestats의 첫 인게임 프레임을 받은 뒤 게임 시간이 1분에 도달하면 배팅을 닫는다.
- livestats를 받지 못하는 장애 상황에서만 공식 일정 시작 20분 후를 안전 마감 시각으로 사용한다.

### 다음 세트

- 원칙적으로 이전 세트의 livestats `gameState=finished` 시각부터 다음 세트 배팅을 연다.
- 종료 프레임을 받지 못하고 공식 완료 상태를 처음 확인한 경우에는, 그 관측 시각부터 연다.
- 실제 다음 세트의 시작을 확인하면 게임 시간이 1분에 도달할 때 배팅을 닫는다.
- 다음 세트 시작을 아직 확인하지 못한 경우에는 오픈 시점부터 20분을 안전 마감 시각으로 사용한다.
- 실제 시작 시각을 확인한 뒤에는 일시적인 캐시 공백으로 안전 마감 시각을 다시 늦추지 않는다.

### 화면 노출

- 첫 세트 배팅은 라이브 시작 전에도 열릴 수 있으므로, 배팅 카드는 실제 `OPEN` 이벤트에 연결된
  예정·라이브 매치만 조회하는 `GET /api/betting-candidates`로 노출한다.
- `GET /api/matches/{externalMatchId}/betting-events/current`은 배팅 가능 여부만 제공하며,
  마감 시각이나 남은 시간은 응답하지 않는다.

## 배팅 등록 규칙

- 현재 `OPEN` 상태이고 배팅 기간 안에 있는 이벤트에만 배팅할 수 있다.
- 사용자는 같은 배팅 이벤트에 한 번만 배팅할 수 있다.
- 선택한 팀은 해당 이벤트의 두 참가 팀 중 하나여야 한다.
- 배팅 포인트는 1,000포인트 이상 100,000포인트 이하다.
- 배팅 등록 시 사용자 포인트를 즉시 차감하고 `STAKE` 원장을 기록한다.

## 풀배당 정산 규칙

- 정산은 이벤트가 `CLOSED` 상태이고 세트 승자가 확정된 뒤에만 수행한다.
- 정산 대상은 해당 이벤트에서 아직 처리되지 않은 `PLACED` 상태의 모든 사용자 배팅이다.
- 총 풀은 정산 대상 배팅금의 합이다.
- 운영 수수료는 총 풀의 **10%를 소수점 버림**해 계산한다.
- 배당 풀은 `총 풀 - 운영 수수료`다.
- 적중자는 자신이 건 포인트 비율에 따라 배당 풀을 나눈다.
- 개별 적중 지급액은 아래 식으로 계산한다. 지급액에는 적중자가 처음 건 포인트의 반환분이 포함된다.

```text
운영 수수료 = 총 풀 × 10%
배당 풀 = 총 풀 - 운영 수수료
개별 적중 지급액 = 배당 풀 × 내 배팅금 ÷ 적중 배팅금 합
```

- 실패한 배팅은 `LOST` 상태가 되며 포인트를 지급하지 않는다.
- 적중한 배팅은 `WON` 상태가 되며 계산된 지급액만큼 사용자 포인트를 증가시키고 `PAYOUT` 원장을 기록한다.
- 비례 배분의 소수점 버림으로 남는 포인트는 적중자에게 배분하지 않고 운영 수수료에 포함한다.
- 아무도 실제 승리 팀을 선택하지 않으면 모든 배팅을 `LOST` 처리하고 총 풀 전액을 운영 측에 남긴다.
- 운영 수수료는 적중자에게 지급하지 않는 포인트다.

### 예시

| 구분 | 배팅금 |
|---|---:|
| A팀 적중자 1 | 1,000p |
| A팀 적중자 2 | 2,000p |
| B팀 실패 배팅 | 7,000p |
| 총 풀 | 10,000p |

위 예시에서 A팀이 이기면 운영 수수료는 1,000p, 배당 풀은 9,000p, 적중 배팅금 합은 3,000p다.
따라서 A팀 적중자 1은 3,000p, 적중자 2는 6,000p를 지급받고 B팀 배팅자는 0p를 지급받는다.

## 취소와 멱등성

- 세트가 진행되지 않거나 확정된 승자를 얻을 수 없어 이벤트가 `CANCELLED` 상태가 되면,
  모든 `PLACED` 배팅을 `REFUNDED` 상태로 바꾸고 원금 전액을 돌려준다.
- 취소 이벤트에는 운영 수수료를 적용하지 않는다.
- 정산과 환불은 이벤트 행과 대상 사용자 배팅을 잠근 하나의 데이터베이스 transaction에서 처리한다.
- 이미 `SETTLED` 상태인 이벤트는 다시 정산하지 않는다.
- 사용자 배팅별 `PAYOUT` 또는 `REFUND` 원장은 한 번만 기록한다.

## 정수 포인트 처리

포인트는 정수 단위로만 처리한다.

- 운영 수수료는 `총 풀 × 10%`의 소수점을 버린다.
- 개별 적중 지급액은 비례 배분 결과의 소수점을 버린다.
- 개별 지급액을 모두 더한 뒤 배당 풀에 남는 포인트는 운영 수수료에 포함한다.
- 현재 포인트 원장은 사용자 배팅의 `STAKE`, `PAYOUT`, `REFUND`만 기록한다. 운영 수수료의 별도
  운영 잔고·원장 기록은 현재 범위에 포함하지 않는다.

## 구현 상태

- 현재 구현은 이 문서의 10% 운영 수수료 기반 풀배당으로 정산한다.
